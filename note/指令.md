### 一、 进程管理：启动与彻底关闭

在开发过程中，经常会遇到“端口被占用”或“僵尸进程”，用这些命令彻底清理。

1.  **彻底强杀所有相关进程**（最常用）：
    ```bash
    # 彻底杀掉 minikv 和 隧道，防止旧进程占着坑不拉屎
    sudo killall -9 minikv cloudflared
    ```
2.  **查找 minikv 是否还在后台运行**：
    ```bash
    ps -ef | grep minikv
    ```
3.  **检查端口监听状态**（确认 8080 是否真的启动成功）：
    ```bash
    sudo netstat -tunlp | grep :8080
    # 或者
    sudo lsof -i :8080
    ```

---

### 二、 Cloudflare 隧道管理

1.  **前台启动（看实时域名和报错）**：
    ```bash
    ./cloudflared tunnel --url http://127.0.0.1:8080
    ```
2.  **后台静默启动**：
    ```bash
    nohup ./cloudflared tunnel --url http://127.0.0.1:8080 > tunnel.log 2>&1 &
    ```
3.  **查看隧道分配的域名**（如果是后台运行）：
    ```bash
    grep "trycloudflare.com" tunnel.log
    ```

---

### 三、 使用 cURL 模拟上传测试（核心调试）

不要只依赖网页界面，用 `curl` 可以排除前端 JS 的干扰，直接测试 C++ 后端。

1.  **模拟标准文件上传**（会自动生成 boundary）：
    ```bash
    # 在当前目录下随便找个图 test.jpg，上传到根目录 /
    curl -v -F "file=@test.jpg" "http://127.0.0.1:8080/api/files?path=/"
    ```
2.  **上传并指定目录**：
    ```bash
    curl -v -F "file=@video.mp4" "http://127.0.0.1:8080/api/files?path=/movies/"
    ```
3.  **通过域名测试上传**（走公网路径）：
    ```bash
    curl -v -F "file=@test.jpg" "https://你的随机名.trycloudflare.com/api/files?path=/"
    ```

### 四、 其他 API 接口测试

1.  **测试获取文件列表**：
    ```bash
    curl -v "http://127.0.0.1:8080/api/files?path=/"
    ```
2.  **测试移动文件**（POST JSON 数据）：
    ```bash
    curl -v -X POST -H "Content-Type: application/json" \
    -d '{"old_path":"/","old_name":"1.jpg","new_path":"/photos/","new_name":"2.jpg"}' \
    http://127.0.0.1:8080/api/files/move
    ```
3.  **测试删除文件**：
    ```bash
    curl -v -X DELETE "http://127.0.0.1:8080/api/files?path=/&name=test.jpg"
    ```

### 五、 存储层物理检查（看数据有没有真的存下来）

1.  **检查上传中的临时文件**：
    ```bash
    # 看看你的 g_tmpDir 目录下有没有产生 .upload 后缀的文件
    ls -lh ../data/tmp/
    ```
2.  **检查物理文件仓库**：
    ```bash
    # 按照你的哈希打散算法，看看 files 下有没有生成的子目录
    ls -R ../data/files/
    ```
3.  **查看元数据数据库文件**：
    ```bash
    # 看看 LevelDB 是否产生了文件
    ls -l ../data/meta/
    ```

### 六、 系统环境优化（针对高并发）

如果你发现连接数多了之后报错，通常是 Linux 的文件描述符限制。

1.  **查看当前限制**：
    ```bash
    ulimit -n
    ```
2.  **临时调大限制**（本次登录有效）：
    ```bash
    ulimit -n 65535
    ```

### 💡 针对你“上传失败”的调试绝招：

如果上传还是不成功，请在你的 C++ 代码 `onMessage` 函数最开头加上这行“暴力打印”，然后运行 `curl` 上传：

```cpp
// 在 onMessage 开头
std::cout << "--- 收到原始原始数据包 ---" << std::endl;
std::cout << std::string(buf->peek(), buf->readableBytes() > 500 ? 500 : buf->readableBytes()) << std::endl;
std::cout << "-------------------------" << std::endl;
```

**为什么这么做？**
通过这个打印，你可以一眼看到：
1. `Content-Length` 是否被正确发过来了。
2. `boundary` 到底长什么样。
3. `Buffer` 里的数据是否完整。
